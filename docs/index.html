What it is

A beige box that boots a DOS prompt, and runs real games behind the glass.

DOS ex Machina draws a 1993 PC — the case, the moulding, the speaker grilles, thirty years of wear — and puts a working CRT in the middle of it. It boots: POST, memory count, AUTOEXEC.BAT. From the C:\> prompt you browse a catalogue, download a game, and play it in the tube. When you type EXIT the raster collapses to a dot and the fans spin down.

The games are not emulated. Each one is a native C port of the original, which also ships as a standalone game in its own right. DXM is the optional machine you can put it inside.

Nothing here is a photograph

The machine is solved, not painted.

The case

Drawn procedurally at your display's resolution from signed-distance geometry and a lighting model. Moulding partings, speaker pods, vent cuts, ejector-pin marks, scuffs and yellowing — all computed. A wider screen gets more machine, never black bars.

The tube

Phosphor persistence, barrel curvature, footprint-integrated scanlines, an aperture-grille mask, bloom, and coloured light spilling from the picture onto the plastic around it. Two real knobs under the right speaker set brightness and contrast — grab one and turn it.

The sound

Fan, hum and drive spindle synthesised at run time from measured spectra. The mains switch, the degauss thump, the POST beep. Only the floppy drive sound is sampled.

Getting a game

Type NC. Press Enter. That is the whole of it.

ENTERplay the game, or download it if it isn't on the disk yet F2 · F3 · F4delete it, reset it, update it when a newer release is on offer TABmove to the description and scroll it Ctrl+F10give the mouse to your desktop, or take it back

DXM ships with no games and links none. The catalogue is fetched at run time and cached, so adding a title is an edit to a JSON file rather than a new release — and a machine that has been online once keeps working offline afterwards.

An install fetches the game's module and its data, checks both against a SHA-256, and keeps them in your preferences directory. After that it runs with no network, forever. Game data is never mirrored: for freeware titles the catalogue points at the publisher's own download. Each game also ships as a standalone program in its own right — SkyRoads runs perfectly well on its own.

Download

0.4 Beta — self-contained. Unpack it and run it; nothing to build, nothing to install.

Drag it to Applications. Signed ad-hoc, not notarised, so the first launch is right-click → Open. macOS 11 or newer.

Linux

  • Tarballx86_64
  • Tarballarm64

Unpack and run ./dxm; SDL3 travels with it. ./install.sh adds a menu entry under ~/.local — no root, and it leaves your PATH alone. glibc 2.35 or newer.

DOS ex Machina · disk 3

Windows

  • Zipx86_64
  • Ziparm64

Unpack and run dxm.exe. Unsigned, so SmartScreen interposes once: More info → Run anyway.

Every build needs a graphics driver with OpenGL 3.3, which any computer of the last decade has. All three platforms are verified on real hardware on x86_64; the arm64 builds compile and package but have not yet been watched drawing a frame. Every run writes a dxm.log in the preferences directory that says how far it got and which GL driver it found. Release notes and older builds are on the releases page.

Build it

Needs SDL3, libcurl and zlib. No game checkout required.

git clone https://github.com/pedrocatalao/dos-ex-machina
cd dos-ex-machina
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build -j8
./build/dxm

Then NC at the prompt, and Enter on a game. macOS, Linux and Windows, on x86_64 and arm64, all built by CI.

Porting a game

Three exported symbols, and no dependencies of its own.

A game is a .dxm module opened at run time. It exports dxm_core_get_info, dxm_core_main and dxm_core_audio, hides everything else, and links no SDL and no threading library — which is what makes it loadable everywhere DXM runs. Its ABI version is checked before anything starts.

  • No exit() — the machine has to survive the game
  • Restartable state, so it can be run twice in one process
  • Declared video modes, so the tube knows what it is showing
  • Audio pulled, not pushed

PORTING.md is the normative contract; SPEC.md covers the machine itself.

Questions

Is DOS ex Machina an emulator?

No. The games are native C ports of the original programs, compiled for your computer and loaded as modules. The DOS prompt is a fiction and the CRT is a rendering pipeline; nothing is emulated.

Which games can it run?

Games arrive as .dxm modules through a catalogue the machine fetches at run time. As of 0.4 Beta the catalogue holds SkyRoads. Any DOS game with a native port that follows PORTING.md can be added by editing the catalogue, without a new release of DXM.

Why does my computer warn me the first time I run it?

The downloads are not code-signed yet: macOS asks for right-click → Open on the first launch, and Windows SmartScreen wants More info → Run anyway. Nothing is installed; unpack the download and run it.

Where do the games and settings live?

In your preferences directory: ~/Library/Application Support/DOSexMachina/dxm/ on macOS, ~/.local/share/DOSexMachina/dxm/ on Linux, %APPDATA%\DOSexMachina\dxm\ on Windows. Games go under games/, the CRT settings in crt.cfg, and each run's dxm.log beside them.
